# 创作模式（Creator Mode）重设计方案

> 状态：方向已确认，**P1（一页五步）与 P2 的「资产 / 分镜可编辑」已落地**（当前实现见 `docs/architecture/creator-mode.md`，使用方法见 `docs/user-guide.md`；对照其它平台的旅程调研见 `docs/reference/short-drama-platform-journeys.md`）。本文只保留尚未完成的部分。

## 1. 为什么要重做

对照 LibTV（LiblibAI 的 AI 短剧工作台）的使用体验，当前 Jellyfish 的问题不在单个功能，而在**流程本身要用户自己串**：

| 现状 | 用户感受 |
| --- | --- |
| 从剧本到一段视频要经过 7 个页面：项目列表 → 项目工作台 → 章节 → 分镜列表 → 分镜编辑页 → 分镜工作室 → 生成弹窗 | 不知道下一步该去哪 |
| 页面上全是系统内部状态：待确认 / 提取确认 / 无需提取 / 关联·新建·忽略 / 视频准备度 / `extraction_ready` / 参考模式 `text_only` | 要先学会我们的状态机才能用 |
| 「准备」和「生成」分在两页，镜头没准备好时工作室只给红字，用户要回编辑页逐项处理 | 卡在半路 |
| 没有批量：关键帧、视频都要一个镜头一个镜头点；没有按顺序连播；「后期剪辑」是占位页 | 做完一个镜头就不想做第二个了 |

LibTV 做对的几件事（可借鉴的部分）：

1. **一个入口**：输入想法/剧本，系统把剧本 → 角色 → 分镜 → 视频串起来跑；人只在关键节点做**选择题**（选形象、确认分镜、确认花费）。
2. **画面优先**：分镜板上直接看关键帧缩略图，整组批量生成，单条可重做。
3. **花钱前先确认**：每次消耗积分前先给出计划（镜头数、时长、预计费用）让人确认。
4. **都在一个地方**：不用在页面之间来回跳。

LibTV 的无限画布 / 节点工作流**不借鉴**：它本身就被评价为学习曲线陡；短剧主流程用线性步骤表达更直接。

## 2. 目标体验：一个页面，五步成片

```
作品列表 ──新建作品──▶ 创作页（单页，顶部五步进度）
                        ① 剧本 ──一键拆分镜──▶ ② 角色场景 ──▶ ③ 分镜板 ──▶ ④ 视频 ──▶ ⑤ 成片
                        右侧常驻「导演助手」：当前该做什么 / 进行中任务 / 额度估算 / 专业模式入口
```

### ① 剧本
- 一个大输入框：粘贴剧本或写几句想法；题材 / 画面风格 / 比例用 chips 选，带默认值。
- 「一键拆分镜」：后台顺序执行 **拆镜头 → 识别角色场景道具 → 自动建档并关联 → 填好景别/时长/对白**，页面上只显示 3 行进度和一个日志。不消耗生成额度。
- 完成后自动进入 ②。

### ② 角色场景（已落地）
- 角色卡 / 场景卡 / 道具卡，内容来自提取结果，**已自动确认**（不再有关联 / 新建 / 忽略）。
- 每张卡：生成形象 / 换一张 / 上传自己的图；抽屉里改名称、设定、看并改提示词、选出现镜头、删除；可手动新增；其它集资产可沿用。
- 待做：形象图多候选 4 选 1；多视图（三视图）形象。

### ③ 分镜板（已落地）
- 网格卡片：序号、标题、景别 / 运镜、画面描述、对白、画面里用到的实体、时长、关键帧缩略图、状态。
- 抽屉：保存并生成 / 重画关键帧、上传关键帧、改标题 / 景别 / 运镜 / 画面描述（AI 改写）/ 时长 / 关联实体 / 对白；增删镜头。
- 待做：关键帧多候选选一张；镜头拖拽排序；低成本预演（白模 / 草图）。

### ④ 视频
- 先出**确认单**：镜头列表、每镜时长、参考方式（首帧图 + 描述 / 仅文字）、总时长、模型、预计耗时；点「开始生成」才扣费。
- 之后同一网格变成进度板：排队 / 生成中 x% / 已完成（可播放）/ 失败（显示真实原因 + 重试 + 修改描述）。
- 总进度条；任一镜头完成即可去看成片。

### ⑤ 成片
- 按镜头顺序连播的播放器 + 片段列表（时长、对白）。
- 「下载全部片段」；「合成导出」第二阶段提供（见 §5）。
- 「继续创作第 2 集」回到 ①，复用同一作品的角色与场景。

### 导演助手（右栏，手机上折叠为底部操作条）
- 当前步骤 + 一句话建议 + 主按钮（和页面主按钮一致）。
- 进行中任务（名称 + 进度）。
- 本集额度估算：图片张数 / 视频秒数；说明只在点生成后扣费。
- 「专业模式」入口：现有分镜工作室 / 编辑页保留，供需要参考模式、关键帧角色、对白行、提示词模板的用户使用。

### 导航精简
- 侧栏：**作品** / **素材库** / **设置**。提示词模板、模型管理、Agents、文件管理收进「设置 → 高级」。
- 作品列表改为卡片：封面（第一张关键帧）、进度（分镜 N · 视频 M/N）、「新建作品」大卡直接进入创作页 ①。
- 旧路由全部保留（`/projects/:id/chapters/:cid/studio` 等），从创作页「专业模式」进入；AGENTS.md 中「编辑页 = 准备、工作室 = 生成」的职责不变，创作模式是它们之上的引导层。

### 术语对照（页面上只用左边）
| 创作模式用语 | 现有内部概念 |
| --- | --- |
| 一键拆分镜 | divide-async + extract-async + 自动确认候选 |
| 角色 / 场景 / 道具 | character / scene / prop / costume 实体 + 候选链接 |
| 形象 / 参考图 | 实体图片（image-tasks） |
| 关键帧 | first_frame 分镜帧图片（shot-frame-prompts + frame-image-tasks） |
| 画面描述 | 视频提示词 / 首帧提示词 |
| 生成视频 | 视频任务（参考模式自动选：有关键帧用 first，否则 text_only） |
| 失败原因 | ArkTaskFailedError / ArkApiError 的中文映射 |

## 3. 后端改动（service 层，api 层只收参/鉴权/组装）

| 接口 | 作用 | 说明 |
| --- | --- | --- |
| `POST /studio/chapters/{id}/auto-confirm` | 把章节内所有待确认候选自动确认：按名称创建/复用角色、场景、道具、服装实体并关联；接受全部对白候选；无候选的镜头标记无需提取 | 纯数据库操作，同步返回；复用 `link_existing_asset_for_preparation` / `mark_accepted` / `set_skip_extraction` |
| `GET /studio/chapters/{id}/creator-board` | 创作页一次性聚合：镜头（细节、对白、首帧图 URL、最近视频任务状态/错误/成片 URL）+ 实体（含形象图） | 替代页面上十几个请求 |
| `POST /film/tasks/shot-keyframe` | 单镜头「写首帧提示词 → 生成首帧图」串成一个任务 | 每张卡一个任务、一个进度；复用现有两个任务的实现 |
| `POST /film/tasks/shot-keyframe/batch` · `POST /film/tasks/video/batch` | 批量创建（每镜头一个任务，返回 task_id 列表） | 参考模式自动选择；沿用 inline 执行 |
| `GET /studio/projects` 增加 `cover_file_id` / 进度统计 | 作品卡片封面与进度 | 聚合查询 |

不改状态语义：`shot.status`、runtime task status、`video-readiness` 保持原含义；创作模式只是把「达到 ready」的操作自动化了。

每次 API 变更后运行 `pnpm run openapi:update`，前端全部走 generated client。

## 4. 前端改动

- 新增 `front/src/pages/creator/`：`WorksPage`（作品列表）、`CreatorPage`（单页五步）、`steps/`（ScriptStep / CastStep / StoryboardStep / VideoStep / FinalStep）、`DirectorRail`、`hooks/useCreatorBoard`（轮询 creator-board）。
- 路由：`/projects` → 作品列表（新）；`/projects/:id/create` → 创作页（打开作品的默认页）；旧路由不动。
- 复用：`useRelationTaskPolling`、`taskNotificationHelpers`、`errorMessage.ts`、`useIsMobile`。
- 手机：步骤条横向滚动、卡片单列、导演助手折叠为底部操作条。

## 6. 不做的事

- 不做无限画布 / 节点编辑器。
- 不删除现有专业页面；不改变 `shot.status` / `video-readiness` 语义。
- 不在创作页展示任务中心的调试信息（任务中心继续只放通用任务状态）。
